# PROJECT BRIEF — מערכת ניהול מטפל–מטופל

**גרסת מסמך:** 0.2 · **עודכן:** 2026-08-29 · **סטטוס:** אפיון פונקציונלי + החלטות טכניות ננעלו

---

## 1. מטרה

פלטפורמת Web לניהול תהליך טיפולי מלא בין **מטפל יחיד** למטופליו בתחומי
**נטורופתיה, רפלקסולוגיה ותזונה**: קליטה → תיק אישי + היסטוריה → פגישות → תוכניות → מעקב → תקשורת.
נגישה ממחשב, טאבלט וטלפון, ללא התקנה.

## 2. משתמשים

- **מטפל / מנהל** — הרשאות מלאות: ניהול מטופלים, פגישות, תוכניות, משימות, מסמכים, הודעות, יומן, סוגי טיפול, היסטוריה.
- **מטופל** — גישה לחשבון האישי בלבד: פרופיל, תוכנית, משימות, פגישות, הודעות, מסמכים, היסטוריה חשופה, התראות. **הזנת נתונים עצמאית — שלב 2.**

## 3. הדרישה הקריטית — הפרדת מידע

כל מטופל רואה **אך ורק** את המידע שלו. אין למטופל: חיפוש מטופלים, רשימת מטופלים, גישה למידע/URL/API של מטופל אחר.
הבידוד מיושם **גם ב-UI וגם בשרת/DB**. עמיד לזיוף URL / מזהה / Request / גישה ישירה ל-API.
ההנחה: **כל המידע במערכת רגיש** (מידע בריאות).

## 4. מודולים פונקציונליים (מהאפיון)

Dashboard מטפל · ניהול מטופלים (הוספה/עריכה/חיפוש/סינון/סטטוס) · פרופיל מטופל · תיק מטופל כרונולוגי (Timeline) ·
פגישה טיפולית (פרטים / מצב מטופל / מדדים / טיפול / משימות / המשך) · סוגי טיפול (ריבוי לכל מטופל) ·
מעקב מדדים לאורך זמן · תזונה (תוכנית / ארוחות / ביצוע) · מעקב יומי (מטופל) · משימות למטופל ·
תקשורת (Messaging) · מרכז התראות · יומן ותורים · סנכרון Google Calendar (חד-כיווני) ·
מסמכים + הרשאות צפייה (מטפל בלבד / מטפל+מטופל) · פרטיות ואבטחה · Audit Log · חיפוש (מטפל בלבד) · סטטוסים.

**האפיון המלא המקורי (0.1) שמור כנספח בהיסטוריית השיחה / להוסיף כאן כ-`PROJECT_BRIEF_v0.1_original.md` בעת הצורך.**

## 8. מילון מונחים

| מונח | פירוש |
|------|-------|
| מטפל / therapist | המשתמש המנהל. בגרסה זו — יחיד. יש ישות `therapist` ו-`therapist_id` על כל רשומה מראש. |
| מטופל / patient | מקבל הטיפול. לכל מטופל חשבון משתמש (`user`) עצמאי. |
| תיק מטופל / patient file | התצוגה המרכזית של מטופל — פרופיל + Timeline. |
| Timeline | ציר זמן כרונולוגי המצרף אירועים מכל המודולים (טבלת `timeline_events` פשוטה, append-only). |
| פגישה טיפולית / treatment session | רשומת תיעוד של מפגש טיפולי (≠ appointment ביומן). |
| appointment | תור/פגישה ביומן, מקושר למטופל. |
| תוכנית טיפול / treatment plan | תוכנית פעילה + היסטוריית גרסאות. |
| סוג טיפול / treatment type | נטורופתיה / רפלקסולוגיה / תזונה. מטופל יכול להשתייך לכמה. |
| Field Registry | מנוע השדות הגמישים: טבלת הגדרות שדה + ערכים ב-JSONB, כל שדה עם סכמת ולידציה. |
| מדד / metric | ערך נמדד לאורך זמן (משקל, ל"ד, שינה...). למדדים מוצגים בגרף — עמודה אמיתית, לא רק JSONB. |
| scoping guard | מנגנון אכיפה מרכזי שמונע גישה ל-DB בלי scope של מטפל/מטופל. הבקרה הראשית לבידוד. |
| Audit Log | לוג פעולות: מי, מה, מתי, על איזה מטופל. |

## 9. סקירת שוק והצדקת הבנייה (2026-08)

נבדקו כלים קיימים. **אין מוצר מדף שעונה על שילוב: עברית RTL + רמת פרטיות ישראלית + עומק קליני מובנה + פורטל מטופל דו-כיווני.**

**בינלאומי (עומק קליני, אך אנגלית בלבד + מידע בארה"ב):**
- **Practice Better** — מוביל הנישה. protocol builder, smart forms עם conditional logic, פורטל מטופל מלא, מעקב בין-פגישות. חסרונות: ניווט עמוס, מטופלים מתקשים להיכנס לפורטל, תמיכה איטית.
- **Healthie** — engagement + אפליקציית מטופל טובה. חסרונות: בונה טפסים "לא דינמי", מחיר מטפס.
- **OptiMantra** — התאמה אישית עמוקה של charting/intake. חסרונות: מורכב, setup ארוך, charting מנותק ב"תיבות", תוצאה מאוחרת שוברת רצף.
- **Jane / Cliniko / Carepatron** — UX נקי / רזה / free-tier, אך לא מותאמים לנישה ולא לעברית.

**ישראלי (עברית + ציות, אך רדוד קלינית):**
- **טיפולוג** — מוביל בישראל, עברית מלאה, תזכורות SMS, זול. ממוקד ניהול/גבייה, לא תיעוד קליני עמוק, פורטל מוגבל.
- **קליניקלאוד** — עברית, **רשום בפנקס מאגרי המידע**, הצפנה+גיבוי מוצהרים, ערוץ שיתוף למטופל. אין מדדים/שאלונים/GCal, פורטל חד-כיווני.
- **קומד** — תיעוד לפי תחום, מעקב התקדמות. אין הצהרת ציות, נראה מיושן.

**לקחים שמיושמים אצלנו:** כרטיס המטופל כ-hub (טיפולוג/קליניקלאוד) · תיעוד פר-תחום מאמת את Field Registry (קומד) · smart forms כ-benchmark למנוע (Practice Better) · הזמנת מטופל ב-magic-link בלחיצה אחת (התלונה הרוחבית מס' 1) · מסך פגישה כזרימה אחת, לא "תיבות" (נגד OptiMantra) · להצהיר הצפנה+גיבוי+רישום מאגר (קליניקלאוד) · לשמור על ניווט רדוד ומעט החלטות למסך (נגד Practice Better).

מקורות מלאים: ראה רשומת ADR-011.
